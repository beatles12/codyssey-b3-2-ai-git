1.미션 한눈에 보기

한 문장 요약: git status 와 git diff 로 내 변경 사항을 모으고, AI API 에 보내 받은 글을 커밋 메시지와 PR 제목·본문 초안으로 다듬어 터미널에 출력하는 Python CLI 도구를 만든다.

공식 미션 소개에 따르면 핵심은 '어떤 입력을 주냐'입니다. 단순히 API 를 부르는 데서 끝나지 않고, 프롬프트와 파라미터로 AI 결과의 품질을 직접 제어하는 경험이 목표입니다.

2.프로그램 구조도

프로그램은 역할별로 파일 6개로 나뉩니다. cli.py 가 순서대로 다른 모듈을 부르는 지휘자이고, 나머지 모듈은 자기 일 한 가지만 합니다.

파일한 가지 역할입력 → 출력상태

왜 이렇게 나눴을까? (체크리스트 항목 2 대비)

Git 수집 ↔ AI 호출 분리
  • Git 은 내 컴퓨터 안의 일, AI 는 인터넷 너머의 일 (실패 원인이 다름)
  • AI 없이도 Git 부분만 테스트할 수 있음
  • AI 제공자를 바꿔도 git_collector.py 는 그대로
프롬프트 ↔ 출력 다듬기 분리
  • 프롬프트 = 부탁, formatter = 검사
  • AI 는 부탁을 100% 지키지 않을 수 있으므로 받은 뒤 다시 확인하는 단계가 따로 필요
  • 규칙(72자 등)이 바뀌면 검사 쪽만 고치면 됨

3.Git diff 와 Git log 의 차이

Git 에는 파일이 머무는 세 장소가 있습니다. 명령마다 "어느 장소와 어느 장소를 비교하는지"가 다릅니다.

명령질문보여 주는 것B3-2 에서
git status --porcelain무엇이 바뀌었나?파일 이름 + 상태 코드 (내용 X)✔ 변경 파일 목록, "변경 없음" 판단
git diffadd 안 한 변경은 어떻게?줄 단위 내용 (+ 추가, - 삭제)✔ diff 텍스트 (unstaged)
git diff --cachedadd 한 변경은 어떻게?다음 커밋에 들어갈 내용✔ diff 텍스트 (staged)
git log지금까지 무엇을 커밋했나?커밋 해시, 작성자, 날짜, 메시지✘ 입력 아님 (공식: 수집은 status·diff 범위)

초보자가 자주 하는 실수: git add 를 한 뒤 git diff 만 보면 아무것도 안 나옵니다. 그러면 프로그램이 "변경 사항이 없습니다"라고 잘못 말할 수 있습니다. 그래서 Step 2 에서는 --cached 결과도 함께 모읍니다.

5.API 와 환경변수

API 란?

API 는 다른 프로그램의 기능을 빌려 쓰는 약속입니다. 식당에 비유하면 메뉴판(API 문서)을 보고 정해진 양식의 주문서(요청)를 내면 음식(응답)이 나옵니다. REST API 는 그 주문서를 HTTP 로 주고받는 방식입니다.

HTTP 요청의 부분뜻B3-2 에서
Method무엇을 할지POST (데이터를 보내 글을 만들어 달라)
URL어디로config.PROVIDERS[제공자]['url']
Headers봉투 겉면: 누구인지(인증), 내용 형식API Key, content-type: application/json
Body봉투 속 내용모델, max_tokens, temperature, 프롬프트 (JSON)
Status code결과 번호200 성공, 400/401/429/5xx 실패

왜 코드에 키를 쓰면 안 될까? GitHub 에 올리면 누구나 볼 수 있고, 커밋 기록에 영원히 남으며(지워도 복구 가능), 키를 바꿀 때마다 코드를 고쳐야 합니다. 노출된 키로 남이 요청을 보내면 비용은 내가 냅니다. 실수로 올렸다면 즉시 제공자 사이트에서 키를 폐기하세요.

temperature 와 max_tokens

파라미터뜻낮추면높이면기본값 (config.py)
temperature다음 단어를 고를 때 얼마나 모험할지매번 비슷하고 무난한 표현 → 재현성↑표현이 다양해짐, 엉뚱해질 수도0.3 (범위 0.0~1.0)
max_tokensAI 가 쓸 수 있는 출력 길이의 상한짧아짐, 너무 낮으면 중간에 잘림길게 쓸 여유, 최악의 경우 비용↑1024 (우리 상한 4096)

⚠️ 확인된 주의점: temperature 를 받지 않는 모델이 있습니다.

  • Anthropic 의 Claude 4.7 이후 모델(Haiku 5.5, Sonnet 5.5, Opus 5.5 등)은 temperature 를 바꿀 수 없습니다. 기본값이 아닌 값을 보내면(Opus 계열은 값과 상관없이) HTTP 400 을 돌려줍니다.
  • API 버전 2026-10-21 에서는 모든 모델이 temperature 를 거부합니다.
  • 그래서 이 실습은 anthropic-version: 2023-06-01 과 temperature 를 받는 claude-haiku-4-5 를 기본값으로 두었습니다.
  • 다른 제공자의 일부 최신 모델도 비슷한 제약이 있을 수 있습니다. 공식 문서를 확인하세요.
  • 공식 체크리스트는 "temperature 또는 max-tokens 값을 바꿨을 때 차이 재현"입니다. temperature 를 쓸 수 없다면 max-tokens 로 실험하고, 그 이유를 설명하면 됩니다.

비용은 어떻게 정해질까? — 토큰

AI API 는 보통 토큰(글자를 잘게 나눈 조각) 수로 요금을 매깁니다. 입력 토큰(프롬프트 + diff)과 출력 토큰(AI 가 쓴 글, 최대 max_tokens)을 모두 셉니다. diff 가 길면 입력 비용이, 여러 번 실행하면 전체 비용이 늘어납니다. 그래서 safe-mode 의 전송 제한, 1회 실행 = 1회 호출, --dry-run 이 비용 관리 도구가 됩니다.

항목 2 — 설계를 설명할 수 있는가

  • Git 변경 사항 수집 로직과 AI API 호출 로직을 왜 분리했는지 2절
  • 프롬프트 구성 로직과 출력 포맷팅(길이 규칙 포함) 로직을 어떻게 분리했고, 그 이유 2절 · 6절
  • API 파라미터를 CLI 옵션으로 설계한 이유(재현성/실험 용이성) Step 1
  • 오류 처리(API Key 누락, 네트워크 오류 등)를 어떤 방식으로 구현했고 왜 그렇게 했는지 11절

항목 3 — 파라미터·프롬프트를 설명할 수 있는가

  • temperature 값을 높이거나 낮추면 결과가 어떻게 달라지는지 5절 · Step 8 실험
  • max_tokens 값이 결과물에 어떤 영향을 미치며, 어떤 기준으로 값을 설정했는지 5절
  • 커밋/PR 용도에 맞는 결과를 얻기 위해 프롬프트에 어떤 정보를 포함했고 왜 그렇게 구성했는지 Step 4
  • 길이/형식 규칙을 "재생성"과 "후처리" 중 무엇으로 해결했는지와 그 선택 이유 6절

항목 4 — 실무 관점

  • AI 가 생성한 커밋/PR 텍스트를 바로 사용하지 않고 검토가 필요한 이유 12절
  • git diff 에 민감정보(API Key, 개인정보 등)가 포함될 수 있는 상황과 이를 방지하기 위한 방안 Step 3
  • 실제 팀 프로젝트에 적용한다면 무엇을 가장 먼저 추가·개선하고 싶은지, 그 우선순위 근거 MY_ANSWERS.md Q4-3
